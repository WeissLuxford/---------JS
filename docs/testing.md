# Тесты и проверка

## Юнит-тесты (без зависимостей)

```
node --test tests/unit/*.test.mjs
```
Покрывают правила D&D (`rules.js`, включая состояния, сопротивления и истощение в `phase3.test.mjs`), форматирование заметок, слияние (`sync.js`), описание изменений (`changes.js`), отрисовку всех вкладок на кривых данных и XSS во всех полях.

Сверка расчётов с правилами PHB 2014 / SRD 5.1 (ожидаемые числа взяты из правил, а не из кода):
- `audit-character.test.mjs`: модификаторы, бонус мастерства, спасброски, навыки, пассивные значения, КД во всех доспехах и с Защитой без доспехов, хиты по всем костям, скорость, истощение, сопротивления.
- `audit-magic.test.mjs`: таблицы ячеек (полные, половинные, третичные заклинатели, договор), рост заговоров, лучи, усиление ячейкой, заряды предметов, атаки оружием, криты, эффекты, укрытие, преимущество и помеха.
- `notes.test.mjs`: поиск по формам слов, подсветка и сниппеты, ссылки и упоминания (в том числе экранирование), обратные ссылки, журнал сессий, чистка заметок, рендер вкладки.
- `board.test.mjs`: построение доски (прямые нити, нити через журнал, одиночки), детерминированная раскладка в пределах доски, сохранённые места.
- `inventory.test.mjs`: контейнеры, циклы, вес с учётом «не при мне» и сумки хранения, пороги нагрузки.
- `backup.test.mjs`: частота автокопий, лимит, переполнение хранилища, недельная подсказка, имя файла.
- `creator.test.mjs`: сборка персонажа из мастера (хиты, КД, спасброски, навыки, сопротивления, умения, снаряжение) для нескольких сочетаний рас и классов, таблицы мастера.
- `features-lib.test.mjs`: данные библиотеки умений (поля, действия, формулы использований на живом персонаже, все классы и расы), перенос в лист, подбор по подклассу.
- `levelup.test.mjs`: повышение уровня колдуна (умения Исчадия, выбор заклинаний и воззваний, таблицы).
- `audit-flows.test.mjs`: отдыхи и кости хитов, спасброски от смерти, мгновенная смерть, временные хиты, концентрация, монеты, опыт, вес, таблицы классов и повышение уровня. `sheet-rolls.js`, `sheet-dialogs.js`, `sheet-levelup.js` гоняются через поддельный DOM; `mutate`, `setHp`, `curHp` в тесте скопированы из `sheet.js`, при их правке обнови копию. Запускаются и в GitHub Actions на каждый push (`.github/workflows/test.yml`).

## Правила доступа на эмуляторе

Нужны Java 21 и пакеты из `package.json` (`npm install`).

```
npx firebase emulators:start --only firestore,auth --project dnd-char-sheet-71645
node tests/rules/rules.test.mjs
```
Тест сам подставляет тестовый uid админа вместо `ВСТАВЬ_СВОЙ_UID`. Порт эмулятора меняется переменной `FIRESTORE_PORT`.

Для эмулятора нужен файл `firebase.json` рядом (в репозиторий не кладём):
```
{
  "firestore": { "rules": "firestore.rules" },
  "emulators": {
    "firestore": { "host": "127.0.0.1", "port": 8080 },
    "auth": { "host": "127.0.0.1", "port": 9099 },
    "ui": { "enabled": false },
    "singleProjectMode": true
  }
}
```

## Сайт на эмуляторе

1. Запустить эмуляторы (как выше) и `python3 -m http.server 8765`.
2. Открыть `http://localhost:8765/?emu#/`. Флаг `?emu` работает только на localhost.
3. Войти без Google: в консоли браузера `await window.__emuSignIn("sub-a", "alice@example.com", "Alice")`.
4. Чтобы стать админом, вставить uid вошедшего пользователя в правила эмулятора вместо тестового.

## Сквозные проверки в браузере

Сценарии лежат в `tests/e2e/` (31 файл, около 450 проверок). Запуск всех:

```
docker compose up -d              # или python3 -m http.server 8765 & там, где нет Docker
node tests/e2e/run.mjs            # все
node tests/e2e/run.mjs notes2 creator   # выборочно
```
Пути к Chromium и `playwright-core` берутся из `tests/e2e/env.mjs` (переопределяются `CHROME_PATH`, `PW_CORE`; на Windows владельца `PW_CORE=file:///C:/Users/Luxford/AppData/Local/npm-cache/_npx/e41f203b7505f1fb/node_modules/playwright-core/index.mjs`, `CHROME_PATH=C:/Users/Luxford/AppData/Local/ms-playwright/chromium-1234/chrome-win64/chrome.exe`), скриншоты пишутся во временную папку `dnd-e2e`. Каждый сценарий открывает чистый браузер в локальном режиме (запросы к Google блокируются), печатает строки `PASS`/`FAIL`. Что покрывают: `smoke` (вкладки, назад, мобильная вёрстка), `atk`/`eff`/`temp`/`audit` (атаки, эффекты, хиты, смерть), `lvl`/`lvl2` (повышение уровня), `notes2` (журнал, ссылки, поиск, доска «Важное»), `flib` (общая библиотека), `creator` (мастер создания), `inv` (контейнеры, копии), `board` (доска расследования), `wand`/`wand2`/`lib` (палочка и заклинания), `offline`, `pwa`, `fx`, `order`, `pin`, `conv`, `accent`, `life`, `am`, `ia` (меню с группами, переключатель пояснений, вдохновение в полосе хода, характеристика заклинаний), `icons` (иконки в строках библиотеки), `links` (оружие и заклинания сами в бою, проверка листа, эффекты хитов, экран не гаснет), `templates` (готовые персонажи на главной, просмотр, забрать, убрать и вернуть), `shake` (бросок встряской), `packs` (наборы снаряжения, мешочек с компонентами, контейнеры и наборы в библиотеке, быстрая корзина), `achtoast` (нажатие на попап достижения открывает список на нём), `iconpick` (поиск иконки в редакторе), `visual` (скриншот-тесты).

Playwright (`playwright-core`) с Chromium. Пример сценария: создать лист, открыть его гостем, включить ссылку, пригласить редактора, убрать, удалить лист и попробовать занять его id. В headless Chromium по умолчанию скрыты полосы прокрутки: для проверки стилей запускать с `ignoreDefaultArgs: ['--hide-scrollbars']`. Локальный режим: блокировать запросы к `gstatic.com` и `googleapis.com`.

## Порядок перед публикацией

Публиковать только после полностью зелёного прогона: `node --test tests/unit/*.test.mjs` и `node tests/e2e/run.mjs` с итогом «сценариев с ошибками: 0». Один раз сценарий упал случайно и прошёл при повторе; если такое повторится, выяснить какой, а не публиковать «на авось».

Сервер для e2e: `curl -s -o /dev/null localhost:8765 || docker compose up -d` (без Docker: `python3 -m http.server 8765 &`). Не останавливать его через `pkill -f "http.server 8765"`: шаблон совпадает с самой командой и убивает оболочку.

Иконки: посмотреть все разом можно, отрисовав `icon(name)` для каждого ключа из `js/icons.js` на тёмном фоне в Playwright (контакт-лист, 12 в ряд, подписи ключами); новые варианты сравнивать там же на 56 и 20 пикселях.

## Скриншот-тесты

`tests/e2e/visual.mjs` снимает главную и все вкладки листа Кириона на телефоне (390×844) и компьютере (1280×900) и сравнивает с эталонами `tests/visual/*.jpg`. Время заморожено на 2026-10-01 12:00, анимации, всплывающие сообщения и погода скрыты. Порог: точка считается другой при разнице больше 48 по каналу, тест падает, если таких больше 0,5%. При падении в папке `tests/visual/dnd-e2e/` (не в git) лежат `visual-<имя>-actual.jpg` и `visual-<имя>-diff.png` (красным то, что изменилось).

Снимается всегда в одном Linux-контейнере: образ `dnd-visual` (`tools/visual.Dockerfile`, официальный Playwright 1.63 на Ubuntu Noble), сервис `visual` в `docker-compose.yml` с профилем `tools` (от `docker compose up -d` не стартует). Тест блокирует Google Fonts, поэтому текст рисуется системными шрифтами, а они в Windows и Linux разные: на машине владельца без контейнера тест всегда красный. Часовой пояс и язык зафиксированы (`Europe/Moscow`, `ru-RU`).

- Проверить: `docker compose run --rm visual`. `node tests/e2e/run.mjs` делает это сам, если есть Docker; без Docker (облачная среда) тест запускается прямо и может отличаться шрифтами.
- Изменил вид нарочно: посмотреть картинку разницы, затем `docker compose run --rm -e VISUAL_UPDATE=1 visual` и закоммитить новые эталоны. Первый запуск собирает образ (около 2 ГБ, один раз).

## Сервис-воркер в тестах

На localhost он тоже регистрируется. Чтобы не мешал, открывать с `?nosw` или в Playwright `serviceWorkers: "block"`. Проверка работы без сети: открыть лист, перезагрузить, `context.setOffline(true)`, снова перезагрузить.

## Чего нельзя

Никогда не писать тестовые данные в боевой Firestore. Только эмулятор или локальный режим.
