# Безопасность и доступ

## Модель

- Вход только через Google (`sign_in_provider == google.com`). Анонимные и прочие токены правила не считают пользователем.
- Смотреть лист по ссылке можно без входа, если у листа `visibility != private`.
- Создавать листы может любой вошедший и не запрещённый пользователь. Создатель становится владельцем (`ownerUid`).
- Новые листы создаются закрытыми (`visibility: private`). Кнопки "Копировать" и "Отправить" в окне "Поделиться" включают доступ по ссылке, переключатель его выключает.
- Редакторы приглашаются по Google-почте: адрес попадает в `characters/{id}/acl/main.emails`, правила сверяют его с проверенной почтой из токена. Почты редакторов видит только владелец и админ. Редактор узнаёт о своих правах через `invites/{свой email}/chars/{id}`. Сам лист меняют только владелец и админ: правки редактора уходят предложением в `characters/{id}/proposals/{uid редактора}` (`{at, by, changes[{p, v | d}], summary[]}`, писать может только сам редактор под своим uid, читать и удалять владелец, админ и автор). Владелец видит полоску «предлагает правки» и принимает или отклоняет.
- Владелец сайта (админ) задаётся одним uid в `firestore.rules` (`ВСТАВЬ_СВОЙ_UID`). Админ видит все листы, может править, удалять, забирать бесхозные листы, запрещать аккаунты.
- Запрещённый аккаунт (`bans/{uid}`) может смотреть, но не может создавать и править. Свои данные удалить может (иначе не смог бы удалить аккаунт).
- Поля `ownerUid` и `createdAt` меняет только админ, `ownerName` и `visibility` только владелец или админ. Лист с владельцем нельзя сделать бесхозным.
- Автор правки не подделывается: `updatedBy.uid` и `history.by.uid` обязаны совпадать с uid из токена, время не может быть больше чем на час впереди.
- Удалённый лист оставляет `deleted/{id}`, и создать новый лист с тем же id нельзя.
- Ограничения размеров: имя до 120 символов, портрет до 400 000 символов, не больше 60 полей верхнего уровня, история без портрета, до 20 редакторов.

## Клиентская защита

- Всё пользовательское в `innerHTML` идёт через `esc()`. `normalize()` чистит id сущностей и приводит типы.
- Формулы использований (`evalFormula`) пропускают только цифры и операторы после подстановки переменных.
- Портрет принимается только как `data:image/...`.
- Режим просмотра (`.sheet.viewer`) прячет и блокирует все изменяющие действия. Это удобство, а защита на стороне правил.

## Что осталось и известные ограничения

- Внутри встроенных браузеров (Telegram, Instagram) Google не даёт войти. Сайт показывает подсказку открыть ссылку в Chrome или Safari.
- Бесплатный тариф не даёт бэкапов. Владелец сайта скачивает их кнопкой "Бэкап" на главной.
- Против скриптового спама следующий шаг App Check с reCAPTCHA v3 (бесплатно).
- Почта с точками в Gmail (`a.b@gmail.com` против `ab@gmail.com`) не нормализуется: приглашать нужно по точному адресу аккаунта.

## Проверка

Правила покрыты тестом `tests/rules/rules.test.mjs` (45 проверок: рабочие сценарии клиента и попытки злоупотреблений). Перед любой правкой `firestore.rules` прогоняй его на эмуляторе (`docs/testing.md`).
